# PORT レポートビューアー

初期状態ではデータはありません。9レポートと売買台帳のExcelを選択し、新規取引を確認してから「計算して表示」を押します。選択・確認だけでは計算結果を更新しません。処理とデータ保存はこのPC内で行い、外部サーバーへは送信しません。

## はじめに

1. Python 3.11以降を用意します。社内PCでは社内のソフトウェア導入手順に従ってください。
2. プロジェクトを展開し、初回のみ `setup.cmd` をダブルクリックします。この手順ではPythonパッケージのダウンロードが必要です。
3. `start.cmd` をダブルクリックすると、`http://127.0.0.1:8777/` が開きます。起動ウィンドウを閉じるとサービスが停止します。
4. 下記のレポート9ファイルと、更新した「売買台帳.xlsx」を選択します。
5. 「新規取引を確認」で新規・変更・取消を確認します。
6. 両方のファイルが揃ったら「計算して表示」を押します。計算が成功すると分析レポートを開きます。

新規取引の確認にはWindows版Bloomberg TerminalへのログインとDesktop APIが必要です。保存済みHTMLの閲覧にはAPIもPythonも不要です。PythonがないPCではHTMLを開くだけでExcelを読み込むことはできません。ポートが使用中の場合は、`.venv/Scripts/python.exe app/server.py --port 8774` などで別の番号を指定してください。

FYTDファイルは不要です。「通期（FYTD）」の表示と取り込みは廃止しました。

## 表示と計算方法

- **月次・MTD**：PORTの出力値を表示します。独自計算の結果で上書きしません。
- **指定日から**：初期表示は2026-03-31から日次データの最新日までです。開始日・終了日は手動で変更できます。業種グループ単位のBrinson–Fachler法で計算し、セクターへ集計します。銘柄選択効果には交互作用を含め、多期間はCarino法でリンクします。このモードではFXを独立して分離せず、取引・レバレッジ等の未分解差額も残します。
- **全資産USD仮定**：共通のUSD/JPY換算による概算です。PORTの複数通貨の為替要因分析を再現するものではありません。
- **独自計算とリスクのベンチマーク**：USD収益を、ポートフォリオのJPY/USD収益から逆算した共通の日次換算因子で円換算します。独立して取得した為替相場ではなく、近似的な入力値です。元のJPYベンチマーク収益も比較用に保持します。
- **リスク指標**：日次超過収益 `a = p − b`、年率換算平均超過リターン `mean(a) × 252`、TE `sample_sd(a) × √252`、IRは両者の比率です。ボラティリティは日次収益の標本標準偏差を年率換算します。Betaは日次共分散をベンチマーク分散で除した値です。
- **計算窓**：年度初来と直近20・60収益区間を表示できます。観測数が不足する場合はリスク指標を表示しません。休日の収益は補完しません。
- **累積超過収益**：ポートフォリオとベンチマークの複利収益率の差です。年率IRの分子には直接使用しません。

独自計算はPORTの内部計算と完全には一致しません。入力データと利用権限は社内で管理してください。

## 売買台帳のExcel

配布済みの「売買台帳.xlsx」に既知の31件を記入しています。以後は同じExcelに1行ずつ追加・修正し、.xlsxのまま保存してください。「売買台帳」と「記入ガイド」の2シートです。列名と「売買台帳」のシート名は変更しないでください。

| 列名 | 記入方法 |
|---|---|
| 取引ID | 一意の番号。次の新規取引はT0032など。修正時も同じ番号を使用 |
| 取引日 | yyyy-mm-dd |
| 銘柄コード | Bloombergの完全な銘柄コード |
| 取引区分 | 買付／売却／分割／入金／出金／その他 |
| 数量増減 | 買付は正、売却は負。数量が不明でも金額が判明していれば空欄可 |
| 売買金額（円） | 円単位。買付は正、売却は負。確認済みの売買では必須 |
| 金額区分 | 実額／概算 |
| 関連取引ID | 入替等の対応関係。任意 |
| 備考 | 取引理由、概算根拠、未確定事項 |
| 確認状態 | 確認済み／未確認／取消 |

既存の金額は評価額ベースの概算で、約定実額ではありません。確認済みの買付・売却のみ金額に集計します。分割を売買金額に計上することはありません。

## 新規取引の確認と計算

「APIで新規取引を確認」は、Bloomberg Desktop APIのPORTFOLIO_DATAを日次取得し、保有数量の差を台帳と照合します。ポートフォリオIDは毎回入力し、設定・台帳・HTML・公開用パッケージには保存しません。API要求の一時ファイルは処理後に削除します。確認終了日だけこのPCに保存します。初回は年度初から取得し、以後はキャッシュと直近3日の再取得を使用します。過去の持倉が遡及修正された場合は、このPCのdata/positionsをバックアップ後に削除して再確認してください。

未記載の数量変化がある場合、「候補入りExcelをダウンロード」で既存行を保持した台帳を受け取れます。銘柄コード・数量増減・検出区間は自動記入します。新規候補は検出日を仮の取引日、数量の符号を買付・売却、円建て時価総額÷保有数量×数量増減を概算金額として自動記入します。全売却は前日の評価単価を使用します。内容を確認・必要に応じて訂正し、「確認済み」に変更して再アップロードしてください。同じ銘柄・数量の既存行が検出日の前後3日以内に1件ある場合は、追加せず既存行を日付差異の確認対象とします。実際の取引日や金額は保持し、確認状態だけ未確認に戻します。追加列の検出IDは照合用です。変更しないでください。

数量変化は約定明細ではありません。分割・移管等も含み、同日内で数量が相殺される売買は検出できません。検出日は取引日とは限らず、金額は約定実額ではなく評価額ベースの概算です。APIで対応する変化がない台帳行は別途表示し、削除しません。APIエラーを「取引なし」と扱うことはありません。

前回計算時の台帳とのID比較も併記します。既存行を削除した場合は行を戻すか「取消」にしてください。未確認行や未記載候補が残る間は計算できません。API確認期間はレポート終了日まで必要です。

## HTMLの保存と再閲覧

計算成功ごとに結果を保存し、更新画面の「保存済みレポート」に一覧表示します。「開く」で過去の結果を表示し、「HTMLをダウンロード」で1ファイルとして保存できます。分析画面上部の「HTMLを保存」からも取得できます。

保存したHTMLはデータ・計算処理・図表を内包します。通常のブラウザーでダブルクリックして開くと、再アップロードやサーバー起動なしで、タブ切替・期間変更・グラフ操作ができます。内容は保存時点のデータで、自動更新はされません。新しいデータを反映するときだけ再計算してください。

## GitHubとデータの管理

- `app/` はプログラムです。実取引を含む「売買台帳.xlsx」は別途、非公開で保管してください。
- `data/` にはExcel原本、台帳、通知、生成HTML、過去の更新結果を保存します。これらは非公開データです。`.gitignore` でプログラム以外を原則除外します。
- **フォルダー全体をGitHubのWeb画面にドラッグしてアップロードしないでください。** Web画面でのアップロードにはローカルの `.gitignore` が適用されません。強制追加も使用しないでください。
- `python package_public.py` で `dist/portfolio-report-viewer-source.zip` を作成します。明示的なファイル一覧に基づいてプログラムのみを収録するため、データ読み込み後も非公開データは含まれません。GitHubへはこのZIPを展開した内容を登録し、会社側でレポートと台帳を改めて読み込んでください。
- `data/runs/.../report.html` はデータを内包したレポートで、オフラインでも閲覧できます。ただし非公開データを含むため、GitHub Pages等で公開しないでください。

サービスはこのPCの127.0.0.1でのみ動作し、他のPCから直接アクセスすることはできません。BQL・メール送信・保存フォルダーの自動監視は行いません。Bloomberg APIは確認ボタンを押したときだけ呼び出します。取引の変更は「新規取引を確認」を押した時点で表示します。レポート上部の「取込・履歴」から戻れます。

## バックアップと確認

`data/` を保存すると、前回のレポート、台帳、既読状態を保持できます。プログラムだけでは非公開データを復元できません。正常に読み込んだ過去の結果は `data/runs/` に残るため、更新に伴って保存容量が増えます。

`python -m unittest discover -s tests` で初期状態、9ファイルの制約、売買の扱い、公開用パッケージの構成を確認できます。`tests/test_analytics.cjs` はNodeを使った計算・描画の確認用です。通常の利用にNodeは必要ありません。

APIで再作成された行は、元の台帳から消えた行と銘柄・取引区分・数量が一致し、日付差が3日以内で双方の候補が一意の場合、「既存取引の更新」として扱います。変更前後を表示し、計算には今回確認した行だけを使用します。候補が複数の場合は自動的に関連付けません。

## GitHub経由のワンクリック更新

- 自宅側：プロジェクト内の **github_upload.bat** をダブルクリック。初回だけログイン・専用リポジトリを設定し、以後は同じリポジトリへプログラムの変更だけを反映します。変更がなければ何も送信しません。
- 会社側：**company_download.bat** 1ファイルを会社PCへ持参してダブルクリック。初回だけ同じリポジトリと保存先を設定します。以後は同じBATで最新版を取得します。既存のdata・台帳・レポート・ローカル設定は保持し、依存パッケージは初回または変更時だけ導入します。起動中のアプリは終了し、更新後にstart.cmdで起動し直してください。
- 前提：両PCにPython 3.11以降とGitHub CLI（https://cli.github.com/）、アップロード側にはGit for Windowsが必要です。会社側にも非公開リポジトリへのアクセス権が必要です。社内のソフトウェア導入・ネットワーク規則に従ってください。
- 初回ログインはGitHubの画面で行います。BATへパスワード・トークン・Portfolio IDを記入しないでください。
- 更新先はBATと同じフォルダーの `.github-transfer-local.json` に保存します。これは公開対象外です。再設定するときはこの設定ファイルを削除してBATを再実行してください。
- アップロードは一時フォルダーに公開ファイルだけをコピーして行います。本機のGit履歴、Excel、生成HTML、台帳、APIキャッシュは送信しません。リポジトリはこのプログラム専用にしてください。強制pushは行いません。
- 会社側のBATは単独で動作します。公開ファイル一覧を読み取り、対象のプログラムだけを更新します。
